# 1 C语言的起源

C语言由**贝尔实验室**的**丹尼斯·里奇**和**肯·汤普逊**在开发UNIX操作系统时设计，是在B语言的基础上进行设计的。

**设计初衷**：将其作为程序员使用的一种编程工具，主要目标是成为**最有用的语言**。

---

**与其他语言的对比**：
- **Pascal**：主要目标是为学习编程原理提供扎实基础
- **BASIC**：开发类似英文的语言，让不熟悉计算机的学生轻松学习

随着计算机的发展，它们已经脱离了主流范畴。取而代之的是为程序员设计开发的C语言，现在已经成为首选的编程语言。

# 2 选择C语言的理由

根据 **TIOBE**、**GitHub**、**Stack Overflow** 等主流排行榜的综合数据：
- 虽然因为AI热潮，Python语言的使用比例暂时提升不少
- 但**C/C++** 在嵌入式和系统层面地位依然稳固

---

## 2.1 设计特性

C语言融合了**计算机科学理论**和**实践控制特性**：
- 让用户能轻松完成**自顶向下的规划**
- 支持**结构化编程**和**模块化设计**
- 用C语言编写的程序更**易懂**、更**可靠**

## 2.2 高效性

C是**高效**的语言：
- 充分利用当前计算机的优势，C程序相对更**紧凑**，运行速度**快**
- 具有通常是**汇编语言**才有的微调控制能力
- 可根据具体情况微调程序，获得**最大运行速度**或**最有效内存使用**

> **汇编语言**：为特殊的中央处理单元设计的一系列内部指令，用助记符来表示；不同的CPU系列使用不同的汇编语言

---

> 针对汇编架构多说几句：常见汇编架构有 **x86**（复杂指令集）、**ARM** 和 **RISC-V**（精简指令集）。我现在使用的HPM芯片采用开源的RISC-V架构，免授权费，但需使用专用工具链。  
> 
> 国内RISC-V发展迅速，已有平头哥、先楫、沁恒等厂商量产芯片，搭配RT-Thread、FreeRTOS等国产/开源RTOS，在IoT和工控领域逐步替代ARM方案。受自主可控政策推动，RISC-V在国内前景广阔。



## 2.3 可移植性

C是**可移植**的语言，这意味着：
- 在同一系统中编写的C程序稍作修改或不修改即可在其他系统运行
- 如需修改，只需简单更改主程序头文件中的少许项

 **注意**：程序中针对特殊硬件设备或操作系统特殊功能编写的部分（如嵌入式的寄存器操作）通常**不可移植**

---

**编译器的普及性**：
- UNIX系统通常将C编译器作为软件包的一部分
- 安装Linux时，通常也会安装C编译器
- Windows和Macintosh都能找到合适的C编译器
- 无论是家庭计算机、专业工作站，还是大型机，都能找到针对特定系统的C编译器

 **总结**：C语言定义了统一的语法和标准库接口，各平台（Windows、Linux、macOS等）的编译器负责翻译成本地机器码，这就是**可移植性的本质**。

<summary> 主流操作系统之间的关系 </summary>

**Unix（1969）** 是操作系统的鼻祖，诞生于贝尔实验室，用 C 语言重写后奠定了现代操作系统的基础。

从 Unix 衍生出两大分支：
- **BSD 分支** → 发展出 FreeBSD，苹果基于此打造了 **macOS** 和 iOS，是正统 Unix（通过官方认证）
- **System V 分支** → 影响了商业 Unix 系统（如 Solaris、AIX）

- **Linux（1991）** 由 Linus Torvalds 从零编写，仅借鉴 Unix 设计理念，代码完全独立，属于"类 Unix"系统。Linux 本身只是内核，搭配不同软件包形成各种**发行版**：
- **Ubuntu** — 最流行的桌面发行版，适合新手
- **CentOS / Rocky Linux** — 服务器常用
- **Debian** — Ubuntu 的上游，稳定性强
- **Arch Linux** — 滚动更新，适合折腾

- **Windows** 则完全独立发展，源自微软的 MS-DOS，与 Unix 家族无关，采用 NT 内核，主导桌面市场。


简单理解：**macOS 是 Unix 的"亲儿子"，Linux 是"精神续作"，Windows 是"另一个家族"**。

## 2.4 强大且灵活

C语言**功能强大且灵活**：
- **UNIX操作系统**大部分是用C语言写的
- 其他语言（如 FORTRAN、Perl、Python、Pascal、LISP、Logo、BASIC）的许多**编译器和解释器**都是用C语言编写的
- 可用于解决**物理学和工程学**的问题
- 甚至可用于制作**电影的动画特效**

 举例：在UNIX机上使用FORTRAN时，最终是由C程序生成最后的可执行程序

> **Q：什么是编译器和解释器**  
A：编译器（Compiler）把整个源代码一次性翻译成机器码，生成可执行文件，所以无运行时开销，但是需要先编译。代表语言：C、C++、Rust、Go  
解释器（Interpreter）逐行读取并执行源代码，不生成可执行文件，因为无需编译，改完即跑，所以开发快，但运行较慢。代表语言：Python、JavaScript、Ruby

> **Q：为什么操作系统和编译器/解释器多用C语言编写**  
A: 因为操作系统需要直接操作硬件，高性能，管理内存，以及最重要的可移植性。  
编译器/解释器本身也是程序，需要高性能，生成机器码，管理内存，同样需要可移植。  
C 语言是连接硬件和高级语言的桥梁，既能操控底层，又比汇编高效，所以操作系统和编译器都选择用它来写。  


## 2.5 面向程序员

C 语言是为了满足程序员的需求而设计的，程序员利用 C 可以：
- **访问硬件**、**操控内存中的位**
- 使用**丰富的运算符**，简洁地表达自己的意图

**伤敌一千自损八百**：
- C 没有 Pascal 严谨，但比 C++ 的限制多
-  **优点**：许多任务处理非常简洁（如转换数据格式）
-  **缺点**：可能会犯一些莫名其妙的错误，这些错误不可能在其他语言中出现

 **C 语言在提供更多自由的同时，也让使用者承担了更大的责任**

另外，大多数 C 实现都有一个大型的库，包含众多有用的 C 函数，用于处理程序员经常需要解决的问题。

> 比如**先楫自研的 hpm_math 库**，API 类似于 CMSIS-DSP，包含基础数学函数（**sin、cos、sqrt** 等）、**矩阵运算**、**FFT/IFFT**、**滤波器**（FIR/IIR）、**统计函数**。直接调用可以获得**硬件加速**。实际使用中为了极限的低延迟场景，同时处理几十个存放 ADC 采集的数组，就可以调用它的向量加法函数获得加速。

## 2.6 缺点是什么

 **"能力越大，责任越大"**

**C语言的主要缺点**：
1. **危险且难以察觉的责任** — 例如涉及**指针**的错误
2. **紧凑简洁 + 大量运算符** — 编写让人费解的代码非常轻松，以至于产生了 **年度代码混乱大赛**（IOCCC）：看谁写的代码最混乱，难以让人理解。

## 3 C语言的应用范围

### 历史发展

**上世纪80年代**：
- C语言已成为小型计算机 **UNIX系统** 的主流语言
- 后来应用范围拓展到 **微型机（PC）** 和 **大型机**

**C++ 的诞生**：
- 很多软件公司开始使用 **C++** 开发大型编程项目
- 在 C 语言基础上嫁接了 **面向对象编程工具**
- 通过对语言建模来适应问题，而不是对问题建模以适应语言

> **举例说明**：  
> **C语言方式** — 控制一个电机时，需要把现实问题拆解成 C 能表达的方式：变量、数组、函数、步骤。电机这个概念被拆成零零散散的数据和步骤。  
>   
> **C++ 方式** — 代码结构和现实世界一一对应，电机不再被拆分为数据和步骤，而是作为一个**对象**，考虑它有什么**行为**。

---

### 现状与前景

虽然近几年 **Python**、**Java** 和 **C++** 非常流行，但 C 语言仍是软件业中的 **核心技能**：
- 在最想具备的技能中，C语言通常位居 **前十**
- C语言已成为 **嵌入式系统编程** 的流行语言
- 一些微处理器都在用 C语言进行编程
- 使用率在嵌入式行业中 **稳居第一**

 **结论**：C语言是最重要的编程语言之一，将来也是如此。如果你想找到一份编程相关的工作，被问到是否会 C 语言时，最好回答 **"是"**。

## 4 计算机能做什么

在用 C 语言编程之前，最好先了解一下计算机的工作原理。这些知识有助于理解 C 语言编写程序和运行 C 程序时所发生的事情之间有什么联系。

---

### 4.1 计算机的组成部件

现代计算机由多种部件构成：

| 部件 | 功能 |
|------|------|
| **CPU**（中央处理单元） | 承担绝大部分的运算工作 |
| **RAM**（随机存取内存） | 存储程序和文件的工作区（断电丢失） |
| **永久存储设备** | 机械硬盘/固态硬盘SSD，关机后不丢失数据 |
| **外围设备** | 键盘、鼠标、触摸屏、监视器等，提供人机交互 |

CPU 负责处理程序，接下来我们重点讨论它的工作原理。

---

### 4.2 CPU 的工作原理

CPU 的工作非常简单（至少从以下简短的描述中看是这样）：

**基本流程**：
1. 从内存中获取一条指令
2. 执行这条指令
3. 获取下一条指令
4. 执行……（循环往复）

 **性能指标**：1GHz 的 CPU 一秒钟能重复这样的操作大约 **十亿次**，因此 CPU 能以惊人的速度从事枯燥的工作。

---

**CPU 的工作区**：
- CPU 有自己的小工作区 — 由若干个 **寄存器** 组成
- 每个寄存器都可以储存一个数字
- 一个寄存器（PC）储存下一条指令的内存地址
- CPU 使用该地址来获取和更新下一条指令
- 在获取指令后，CPU 在另一个寄存器（IR）中储存该指令，并更新PC储存下一条指令的地址

**指令集**：
- CPU 能理解的指令有限（这些指令的集合叫作 **指令集**）
- 这些指令相当具体，其中许多指令都是用于请求计算机把一个数字从一个位置移动到另一个位置
- 例如：从内存移动到寄存器

>  **寄存器详解**：  
> **PC**（Program Counter，程序计数器） — 存储下一条要执行的指令内存地址，每执行完一条指令，PC 自动更新指向下一条指令  
>   
> **IR**（Instruction Register，指令寄存器） — 存储当前正在执行的指令本身，CPU 从 PC 指向的地址取出指令后，放入 IR 进行解码和执行

---

### 4.3 机器语言编程

**计算机的工作原理**：
- 你希望计算机做某些事，就必须提供特殊的 **指令列表**（程序）
- 确切地告诉计算机要做的事情以及如何做
- 你必须用 **机器语言** 创建可供计算机执行的程序

 **这是一项极其无聊且费时间的任务**

**举例：完成两数相加**，站在机器的角度需要完成以下步骤：

> 1. 从内存某个位置 **A** 拷贝一个数字到 **寄存器1**
> 2. 从另一个位置 **B** 拷贝一个数字到 **寄存器2**
> 3. 把 **寄存器1** 和 **寄存器2** 的内容相加
> 4. 结果存到 **寄存器1**
> 5. 最后把 **寄存器1** 的内容拷贝到内存 **C**
>
> 你要做的很 "简单" — **用数字来表示以上的每个步骤**
